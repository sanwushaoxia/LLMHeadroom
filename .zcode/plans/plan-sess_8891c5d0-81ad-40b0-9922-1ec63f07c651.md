# Headroom — 上下文压缩框架搭建计划

## 目标
在空目录 `/home/wyh/Automation/Headroom` 从零搭建一个 Python 实现的上下文压缩框架:多种专用压缩器 + ContentRouter 自动路由 + CCR(压缩后可取回原文)机制,首版以 MCP Server 形式接入 Claude Code/Cursor,CCR 原文用 SQLite 持久化。

## 技术选型(已确认)
- **语言**:Python 3.13(环境已有;无 uv,用 venv + pip)
- **MCP SDK**:官方 `mcp` 包(`mcp.server.fastmcp.FastMCP`)
- **存储**:SQLite(stdlib `sqlite3`),内容 zlib 压缩落盘,带 TTL
- **CLI**:argparse(stdlib),零额外依赖;唯一第三方依赖是 `mcp`

## 核心机制设计

**1. 压缩器接口**:`detect(content)->置信度0~1` + `compress(content)->压缩文本`。Router 取置信度最高且超阈值的压缩器,否则落到 TextCompressor;支持 `router.register()` 扩展自定义压缩器。

**2. 各压缩器算法(首版规则式,确定性、可测试)**
- **LogCompressor**(检测:日志时间戳/level 模式):重复行折叠为"×N 次,首末时间戳";堆栈跟踪只留首尾帧并标注省略帧数;默认过滤 DEBUG/INFO 保留 WARN/ERROR;保留头尾锚点行。
- **JsonCompressor**(检测:`json.loads` 成功):长数组只留首尾 N 项并标注总数;相似对象的列表提炼公共 schema + 逐项差异;可选丢弃 null/空字段。
- **CodeCompressor**(检测:代码特征——def/class/import/分号+大括号等):函数体超长时只留签名+docstring+"… N 行省略 …";压缩连续空行;折叠连续 import。
- **TextCompressor**:空白规整、连续重复行去重。

**3. CCR 机制**
- 压缩结果头部嵌入标记,如 `[headroom:ccr://a1b2c3d4|orig≈12.3k tok|use headroom_retrieve to fetch original]`,LLM 随时可取回。
- 原文 zlib 压缩存入 `~/.headroom/ccr.db`(可用 `HEADROOM_HOME`/`HEADROOM_DB` 覆盖),TTL 默认 72h(`HEADROOM_TTL_HOURS`),写入时惰性清理过期条目。
- 只有当压缩率 ≥ 30%(`HEADROOM_MIN_RATIO`)时才走 CCR 并加标记,否则原样返回(避免无意义开销)。
- token 估算用 len/4 启发式(不引入 tokenizer 依赖)。

**4. MCP Server**(stdio,`python -m headroom.mcp_server` 或 `headroom mcp` 启动)
- `headroom_compress(content, hint?)` → 压缩文本 + 压缩统计
- `headroom_retrieve(ccr_id, mode="full"|"preview")` → 取回原文/预览
- `headroom_stats()` → 库内条目数、累计节省 token
- README 写明挂载方法:`claude mcp add headroom -- python -m headroom.mcp_server`(Cursor 同理配 mcp.json)

**5. CLI**:`headroom compress <file|->`、`headroom retrieve <id>`、`headroom stats`、`headroom mcp`。

## 配置项(env 可覆盖)
`HEADROOM_DB`、`HEADROOM_TTL_HOURS=72`、`HEADROOM_MIN_RATIO=0.3`、`HEADROOM_MAX_CONTENT=2MB`、各压缩器阈值。
