# CLI JSON 默认配置计划

## 目标
让下面的长命令可以简化为：

```bash
headroom compress output/workflow.log
```

默认从用户配置文件读取：

```text
~/.headroom/config.json
```

保存以下 CLI 压缩默认值：

```json
{
  "encoding": "latin-1",
  "max_content": 10485760,
  "hint": "log"
}
```

不修改核心 Python/MCP `Config` 职责，也不读取 `.zcode/config.json`；`.zcode/config.json` 继续只用于 ZCode MCP。

## 配置优先级

按字段合并：

- `--encoding` > JSON `encoding` > `utf-8`
- `--hint` > JSON `hint` > 自动路由(`None`)
- `--max-content` > `HEADROOM_MAX_CONTENT` > JSON `max_content` > `2097152`

配置文件路径优先级：

- `compress --config PATH`
- `HEADROOM_CONFIG`
- `~/.headroom/config.json`

默认文件不存在时静默使用内置默认；显式指定的文件不存在、JSON 损坏或字段非法时返回稳定的 `CONFIG_ERROR`。

## 实施改动

### 1. 新增 CLI 配置加载模块

新增 `headroom/cli_config.py`：

- 定义 `CliDefaults` 数据模型，字段为 `encoding`、`max_content`、`hint`。
- 读取 JSON 文件并严格校验：根对象、只允许这 3 个字段；`encoding` 必须是有效 codec；`max_content` 必须是正整数且拒绝 bool；`hint` 必须为 `log/json/code/text` 或 `null`。
- 使用 `codecs.lookup()` 提前验证编码名称。
- 将坏 JSON、未知字段、错误类型、显式路径不存在统一转换为 `ConfigError`。
- 默认路径缺失返回空配置。

### 2. 修改 `headroom/cli.py`

- `--encoding`、`--hint`、`--max-content` 的 argparse 默认值改为 `None`，以便区分“未指定”和“显式覆盖”。
- `compress` 子命令新增 `--config PATH`。
- 在 `cmd_compress` 的 `try` 内完成配置加载和 `Headroom` 构造；使用 `hr = None`，确保配置错误时不会在 `finally` 中引用未初始化对象。
- 解析最终配置后再读取输入文件和压缩：
  - encoding 传给 `_read_source()`；
  - hint 传给 `Headroom.compress()`；
  - max_content 作为本次 `Config` 的显式值传入，但只有在 CLI/JSON 生效且没有 `HEADROOM_MAX_CONTENT` 环境变量时覆盖核心默认，确保环境变量优先于 JSON。
- 保留现有显式命令行为和 `--json` 输出。
- 解码错误继续返回 `INPUT_DECODE_ERROR`；配置错误返回 `CONFIG_ERROR`。

### 3. 保存当前用户默认值

创建用户配置目录和文件：

```text
/home/wyh/.headroom/config.json
```

内容保存当前工作流需要的 `latin-1`、10 MiB 和 `log` 默认值，使用户重新打开终端后可以直接执行短命令。

仓库中不写入个人路径配置；如需团队共享，README 提供 `--config ./headroom-config.json` 示例。

### 4. 测试

更新 `tests/test_cli.py`：

- 无参数命令读取 JSON 默认值，并成功处理 latin-1 日志。
- `--encoding`、`--hint`、`--max-content` 分别覆盖 JSON。
- `HEADROOM_MAX_CONTENT` 覆盖 JSON，CLI 参数再覆盖环境变量。
- `--config PATH` 和 `HEADROOM_CONFIG` 路径优先级。
- 默认配置文件缺失时回退到现有默认。
- 坏 JSON、未知字段、非法 encoding/hint/max_content、显式文件不存在返回 `CONFIG_ERROR`。

更新 `tests/conftest.py`：

- 隔离 `HOME` / `HEADROOM_CONFIG`，避免读取真实用户配置。
- 保留现有临时数据库隔离。

### 5. README 用户指南

新增“CLI 配置文件”章节：

- 配置文件路径和 JSON schema。
- 直接运行 `headroom compress output/workflow.log` 的示例。
- `--config` 项目级配置示例。
- 参数优先级。
- 明确 `max_content` 按解码后文本的 UTF-8 bytes 计算；`latin-1` 适合无法按 UTF-8 解码的历史日志。
- 说明 `.zcode/config.json` 是 ZCode MCP 配置，不能混入 Headroom CLI 默认值。

## 验收标准

- 用户直接运行 `headroom compress output/workflow.log` 成功，无需携带三个参数。
- CLI 显式参数仍能覆盖 JSON 默认值。
- `HEADROOM_MAX_CONTENT` 仍优先于 JSON 文件值。
- 配置错误返回 `CONFIG_ERROR`，不泄漏 traceback。
- 现有测试和新增配置测试全部通过。
- 非 UTF-8 大日志可以用配置文件自动完成解码和压缩。
